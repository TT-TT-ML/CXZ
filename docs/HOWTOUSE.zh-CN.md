# CXZ 命令手册（完整版）

> 适用版本：**CXZ 1.2.0**（`CXZ -v` 可查看）
> 本版本只有一种压缩算法：自研 **CXZ**（LZ77 + 自适应二进制算术编码），以及由它衍生的
> 加密容器、目录打包、多线程、进度显示。**不含 ZIP，不含
> rle/huffman/lzw/lz77/deflate/bwt/ac 等任何经典算法**。旧版用这些算法做出的包没法解压，见第 14 节。

程序清单：

```
CXZ.exe     命令行引擎（核心闭源，单文件静态，无外部 DLL 依赖）
CXZQt.exe   Qt 6 图形前端（开源，全流程 QProcess 调用 CXZ.exe，自身不含引擎代码）
```

---

## 1. 一分钟上手

```bat
CXZ album                        :: 目录 -> album.cxz（无口令，纯压缩）
CXZ note.txt                     :: 文件 -> note.txt.cxz
CXZ -p "口令" album              :: 加密压缩，默认 AES-256
CXZ -d album.cxz restore         :: 解到 restore\（目录归档会自动建目录）
CXZ -l album.cxz                 :: 只看内容清单，不解压
```

引擎把「压缩」和「加密」做成一步：给了 `-p` 就加密，不给就只压缩。解压时同理，加密包必须
给同一个口令。

---

## 2. 输出命名与解压目标

| 输入 | 命令 | 输出 |
|---|---|---|
| 文件 `note.txt` | `CXZ note.txt` | `note.txt.cxz` |
| 目录 `album` | `CXZ album` | `album.cxz` |
| 自定义名 | `CXZ note.txt out.cxz` | `out.cxz` |
| 自定义名（`-o`） | `CXZ -o out.cxz note.txt` | `out.cxz` |

- 输出已存在时**不会覆盖**，报错退出；加 `-f` 才覆盖。
- `-d` 时不给第二个参数，就按「去掉 `.cxz` 后缀」命名：`album.cxz` → `album`。
- 目录归档解压到目录；`--to-dir` 可以强制把输出参数当目录（哪怕它看起来像文件名）。

```bat
CXZ -d -f --to-dir album.cxz out\    :: 明确解到 out\，允许覆盖
```

## 3. 目录打包

目录不会被拆成多个文件，而是**打成一个归档**：所有文件 + 所有层级 + 空子目录都记在条目表里。

```bat
CXZ photos                  :: photos.cxz，条目表里是 photos/a.jpg、photos/2024/b.png …
CXZ -d photos.cxz restore   :: restore\ 下原样重建，空目录也会建出来
```

- 归档里存相对路径，解压时拼到目标目录后面，不会写出目标目录之外（防路径穿越）。
- 归档输出如果落在被压缩目录内部，**不会自动排除自己**，重跑会把自己也打进去；建议输出到目录外。

实测（1.2.0，3 条目的目录，含一个空子目录）：

```
cxz+enc: folder of 3 entries, 96 bytes -> 255 bytes  (265.62%)  187.3 ms
cipher: AES-256   kdf: PBKDF2-SHA256 200000 rounds   slots: 1
```

96 字节的极小目录加密后 255 字节是正常的：容器头 + salt + 口令槽 + 条目表本身就有固定开销，
压小文件时这部分无法摊薄。

---

## 4. 压缩档位 `-1` … `-9`

`-1` 最快、`-9` 最小，默认 `-5`。档位只改 CXZ 的匹配器行为（哈希链深度、nice length、
是否惰性匹配），**不改位流格式**：任何档位做出的包，同一个 `CXZ.exe` 都能解。

```bat
CXZ -1 big.log          :: 追求速度
CXZ -9 big.log          :: 追求体积
```

实测（内置自测语料，`-t` 输出）：

| 语料 | 原始 | 压缩后 | 比率 |
|---|---|---|---|
| text（英文散文） | 82 800 | 653 | 0.79% |
| log（重复行很多的日志） | 401 059 | 17 369 | 4.33% |
| source（C++ 源码） | 34 200 | 245 | 0.72% |
| random（不可压缩随机数据） | 1 048 576 | 1 066 673 | 101.73% |

随机数据变大是正常的：压缩器不会假装能压随机数据，此时体积约为原始的 101.7%（容器头开销）。

## 5. 多线程 `-j` 与进度 `-#`

- `-j <1..32>`：把输入按 **4 MiB** 切块，每块内部仍走完整 CXZ 编码，多块并行；解压同样并行。
  默认 4。
- `-#`：打印 25 格进度条 + 百分比 + 预计剩余时间，并在下一行显示当前处理的文件；**不清屏**，
  适合管道和日志。

```bat
CXZ -9 -j 32 -# big.mp4          :: 32 线程 + 进度条
CXZ -j 8 -p "口令" -# photos     :: 加密 + 8 线程 + 进度
```

`-#` 给人看，`--machine` 给程序看，两者用途不同。

## 6. 加密：五档 AES + ChaCha20

```bat
CXZ -p "口令" album                          :: 默认 AES-256
CXZ -p "口令" --cipher aes512 -i 500000 album
CXZ -p "口令" --cipher chacha20 album
```

| 开关 | 取值 | 说明 |
|---|---|---|
| `-p` / `-k` / `--password` / `--key` | 任意字符串 | 口令；压缩=加密，解压=解密 |
| `--pass-stdin` | — | 从标准输入读口令，不留在命令行历史/进程列表里 |
| `--cipher` | `aes64` `aes128` `aes192` `aes256` `aes512` `chacha20` | 默认 `aes256` |
| `-i` / `--iterations` | 10000 … 500000 | PBKDF2-SHA256 轮数，默认 200000；写进文件头，解密时按文件里的值算 |

五档 AES 对应不同轮数（10/12/14 轮），`aes64` 是缩短轮数的轻量档，`aes512` 是加轮数的强化档；
档位越高越慢、越难暴力。`chacha20` 走另一条密码学路径，适合没有 AES 硬件加速的老机器。

加密包的流程是：**整段先压缩，再整体加密，最后对整个文件做 HMAC-SHA256 认证**。随机生成的
DEK（数据密钥）由口令派生的密钥包裹，因此：

- 口令错误 → 包裹解不开 → 直接报错，**一个字节都不会写盘**；
- 文件被改一个字节 → HMAC 校验失败 → 拒绝解压，**不会输出半截垃圾文件**。

从标准输入给口令（不写进命令行历史）：

```bat
CXZ --pass-stdin -d album.cxz out < pw.txt
```

## 7. 口令槽：加口令与原地换口令

一个归档可以带多个口令槽（每个槽独立用一个口令包裹同一把 DEK），方便多人各持一个口令。

```bat
CXZ -p "旧口令" -A "同事的口令" album.cxz      :: 追加一个槽，旧口令仍然有效
CXZ -p "旧口令" -P "新口令"     album.cxz      :: 换掉全部槽，旧口令立即失效
```

- 两种操作都在原文件上重写，先写临时文件再原子替换，失败不会留下半个归档。
- `-A` / `-P` 必须同时给 `-p`（或 `--pass-stdin`）说明当前口令；二选一，不能同时用。
- `-P` 不改变加密等级与 KDF 轮数，只换包裹密钥。

## 8. 列表与机器可读输出

```bat
CXZ -l album.cxz                 :: 人看：名称 + 大小 + 合计
CXZ -l -p "口令" album.cxz       :: 加密包也要给口令，否则读不出条目表
CXZ -l --machine album.cxz       :: 给 GUI/脚本解析
```

加密包会先打印一行容器信息，例如：

```
[cxz v3] AES-256, kdf: PBKDF2-SHA256 200000 rounds, slots: 1, blocks: 1 x 4194304 bytes, raw size: 96
```

`--machine` 的行协议（GUI 依赖它，改动需同步）：

| 行 | 含义 |
|---|---|
| `INFO\|版本\|算法\|加密等级\|轮数\|槽数\|块数\|原始大小` | 容器头信息 |
| `TITLE\|...` | 单文件归档的标题行 |
| `ENTRY\|大小\|名称` | 每个条目一行 |
| `TOTAL\|总字节\|条目数` | 结尾汇总 |
| `RESULT\|ok\|原始\|压缩后` | 压缩/追加完成 |
| `ERROR: ...` | 失败原因（同时退出码非 0） |

## 9. 新建空归档与追加

```bat
CXZ --create empty.cxz                 :: 新建空归档
CXZ --create empty.cxz -p "口令"        :: 新建空加密归档
CXZ --append album.cxz more.txt        :: 往已有归档追加一个文件
CXZ --append -p "口令" album.cxz dir\   :: 加密归档追加（要给口令）
```

- `--append` 解出原有条目表 → 加入新路径 → 整包重新压缩 → 原子替换原文件。
- 追加同名条目会覆盖旧条目（同名判断按归档内相对路径）。
- 空归档可以被 `-l` 正常列出（0 条目）。

---

## 10. 选择性解压

```bat
CXZ -d --only "photos/2024/" album.cxz out    :: 只解某个前缀下的条目
CXZ -d --only readme album.cxz .               :: 只解名字以 readme 开头的条目
```

`--only` 按归档内路径前缀匹配；没匹配到的条目直接跳过，其余不动。配合 `--to-dir` 可以精确控制
落盘位置。

## 11. 自测、基准、版本、帮助

```bat
CXZ -t                 :: 内置自测，全部通过才算可用
CXZ -b big.bin         :: 基准：体积、压缩耗时、解压耗时（含加密一档）
CXZ -v                 :: 版本号与编译器
CXZ -h                 :: 英文帮助
CXZ -help_zh_cn        :: 简体中文帮助
CXZ -help_zh_tw        :: 繁体中文
CXZ -help_ja / -help_ko / -help_ru / -help_fr / -help_es / -help_de
```

`-t` 覆盖哪些内容（1.2.0）：

1. 密码学标准向量：SHA-256 / HMAC-SHA256 / PBKDF2 / ChaCha20、AES-128/192/256（FIPS-197）+ CTR（SP800-38A）。
2. 4 类语料 × CXZ 往返（第 4 节那张表）。
3. 4 组边界输入（空、单字节、5 字节重复、8 字节含控制字符）。
4. 加密/认证：明文包、加密包、错口令拒绝、篡改检测、ChaCha20、五档 AES、50 万轮 PBKDF2、加槽、换口令。
5. 目录归档往返：含空子目录的 6 条目目录，加密压缩后解回并逐文件比对。

通过时最后一行是 `ALL TESTS PASSED (failures=0)`。

`-b` 输出示例：

```
file=big.bin  bytes=1048576

algo       out      ratio   comp ms  decomp ms
cxz        ...      ...      ...       ...
cxz+enc    ...      ...      ...       ...
```

## 12. 错误与退出码

| 场景 | 提示 | 退出码 |
|---|---|---|
| 成功 | — | 0 |
| 用法错误（缺参、未知开关、`-a` 给了别的名字） | `ERROR: ...` / `unknown algorithm: ...` | 1 |
| 运行失败（口令错、CRC/HMAC 不对、文件不存在、拒绝覆盖） | `ERROR: <原因>` | 2 |

常见原因：

| 现象 | 原因 | 处理 |
|---|---|---|
| 解压失败 / 提示需要口令 | 加密包没给 `-p`，或口令错 | 给对口令；口令错不会有任何输出文件 |
| `not a CXZ file (no recognizable header)` | 不是本版本能识别的归档 | 若是旧版其它算法的包，见第 14 节 |
| `refusing to overwrite` | 输出已存在 | 加 `-f` 或换输出名 |
| `ERROR: -i must be 10000..500000` | KDF 轮数越界 | 落在 1 万到 50 万之间 |
| `ERROR: -j must be 1..32` | 线程数越界 | 1..32 |

## 13. 安全边界（诚实版）

保护到的：

- 归档被完整拿走、口令足够强时，**实际不可破解**（AES-256/512 + PBKDF2 20 万~50 万轮）。
- 单字节篡改、截断、拼接都会被 HMAC 拒绝，不会产出半截或错误内容。
- 口令错误时**不写盘**，不会留下可疑的空文件。
- 解压路径限制在目标目录内，条目名里的 `..` 不会穿越出去。

没保护到的（务必知道）：

- **没有前向保密**：口令泄露等于历史归档全泄露。想降低影响就换口令（`-P`）并重新分发归档。
- **没有密钥轮换、没有硬件密钥**：KDF 轮数是唯一可调的「变慢」手段。
- **口令错误与篡改都会报错**：这本身是一个「口令是否正确」的侧信道，任何口令型归档格式（7z、
  ZIP AES）都有同样特性。对抗方式是在解压入口加统一延时与失败计数（由 GUI/服务端做）。
- **不是认证产品**：没有经过任何国家或行业密码认证，不能用于法定「国家机密」场景。

## 14. 从旧版本迁移

- 旧版本的 `.rle` `.huff` `.lzw` `.lz77` `.deflate` `.bwt` `.ac` `.zip` 以及 `-z` / `-u` / `--raw`
  在本版本中**已彻底移除**：源码、命令行开关、帮助文案都不再包含它们。
- 旧版用这些算法做的单文件包（MZP1 容器）仍能被识别，但会明确报
  `this container was made by a legacy codec that is no longer supported`。
- 旧版 CXZ 归档（含加密的）**完全兼容**，照旧 `-d` 解开。
- 迁移建议：用旧版把历史包解成原文件，再用本版本重新压成 `.cxz`（需要保密就一起加密）。
